# 实时识别接入

后台服务经 VehicleControlCenter 分别启动 PLC 通信、打开相机、模型初始化与识别调度。打开相机和初始化模型互不等待；只有实际识别必须在模型初始化成功后执行。模型尚未准备好时，相机回调仍可提交最新通知，不会积压。

三个方法分别处理自己的异常，控制中心只等待宿主停止信号。模型初始化失败不影响开相机和 PLC；单台相机打开失败继续打开其他相机。意外退出的流程不自动重启；PLC 已有的断线重连和单次识别失败后的继续处理保持不变。宿主停止时才统一取消、等待任务并关闭相机。矩形结果发送 PLC 暂未接入。

开相机后按原生相机 ID 登记识别配置，关闭前注销。帧回调只原子替换最新通知，不等待、不调用 SDK、不获取相机生命周期锁。调度器每 10ms 检查一次，轮询各相机；全局最多一个识别调用，每台相机最多一个待处理通知。模型慢时覆盖旧通知，不补做历史帧。无新通知时不识别。

## 配置及观察

- `Vehicle.DetectionModelPath`：填写运行 SDK 的设备上的真实模型路径。
- `Vehicle.Cameras[i].DetectionEnabled`：设为 `true` 启用该相机识别。
- `Vehicle.Cameras[i].Detection.IntervalMilliseconds`：默认 200，表示同一相机两次识别开始至少间隔 200ms，目标上限约 5 次/秒；配置在启动时读取，修改后重启。
- `Vehicle.Cameras[i].Detection.ROI`：填写 X、Y、Width、Height。坐标非负，宽高必须大于零且应位于实际图像内。当前示例宽高为零，启用前必须修改。
- 将 `Logging.LogLevel.TrackedVehicle.Core.DetectionScheduler` 设为 `Debug`，观察相机、触发帧号、结果数及识别耗时。当前仅记录结果摘要，告警和入库尚未接入。

所有相机共享算力，间隔是上限约束，不保证达到目标帧率。回调中的帧号仅为触发信息：LaneDetect 不接收帧号，实际识别哪一帧取决于 SDK。还需在 Linux ARM64 设备上确认 SDK 支持从回调以外的后台线程执行识别。

关闭单个相机先注销 ID、丢弃通知并等待正在执行的识别，然后停止录像和关闭相机。服务停止先取消并等待消费者，再关闭相机。取消令牌无法中断已进入的原生调用，SDK 不返回时关闭也会等待。关闭失败后该相机保持注销状态，需关闭成功并重新打开才恢复识别。

没有额外调用 ClearDetectResult：当前 SDK 未说明是否需要逐帧清理，避免擅自改变结果生命周期。其他业务如直接使用 IDetectManager，仍需自行协调相机生命周期，实时识别统一走调度器。

按相机 ID 管理依赖 SDK 在 CloseCam 成功返回后停止旧回调，再重新打开相机；不再维护额外的 Session。
