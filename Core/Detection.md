# 实时识别接入

后台服务经 VehicleControlCenter 独立启动 PLC 通信和模型初始化；相机流程等待首次收到 PLC 自动模式 3 后打开相机、创建巡检记录，并按 Record.Enabled 启动录像。打开相机不等待模型和数据库；只有实际识别必须在模型初始化成功后执行。模型尚未准备好时，相机回调仍可提交最新通知，不会积压。

三个方法分别处理自己的异常，控制中心只等待宿主停止信号。模型初始化失败不影响开相机和 PLC；单台相机打开失败继续打开其他相机。意外退出的流程不自动重启；PLC 已有的断线重连和单次识别失败后的继续处理保持不变。宿主停止时才统一取消、等待任务并关闭相机。识别成功后立即发送 3 字节结果给 PLC，失败不重发旧结果。

开相机后按原生相机 ID 登记识别配置，关闭前注销。帧回调先按帧序号筛选，只原子替换最新的符合条件的通知；使用独立的短锁保护筛选和提交，不等待识别、不调用 SDK、不获取相机生命周期锁。回调通过容量为 1 的异步通知通道唤醒调度器，不再每 10ms 轮询；全局最多一个识别调用，每台相机最多一个待处理通知。模型慢时覆盖旧通知，不补做历史帧。无新通知时不识别。

## 配置及观察

- `Vehicle.DetectionModelPath`：默认 `robot.rknn`，模型随程序复制到输出和发布目录；相对路径按程序所在目录解析，也可填写设备上的绝对路径。初始化前检查文件存在。
- `Vehicle.Cameras[i].DetectionEnabled`：设为 `true` 启用该相机识别。
- `Vehicle.Cameras[i].Detection.FrameInterval`：默认 5，必须大于等于 1。以每台相机登记后收到的首个帧号为起点，帧号差为间隔的整数倍时提交通知；例如起点为 1 时选中 1、6、11、16……，设为 1 时每帧都可触发。25 FPS 时理想情况下每秒触发 5 次，不再限制识别开始时间必须相隔 200ms。配置在启动时读取，修改后重启；旧的 IntervalMilliseconds 配置应替换为 FrameInterval。
- `Vehicle.Cameras[i].Detection.ROI`：填写 X、Y、Width、Height。坐标非负，宽高必须大于零且应位于实际图像内。启用前应核对配置与实际图像尺寸。
- 每次识别成功以 `Information` 级别记录相机、触发帧号、centerX 及识别耗时，失败以 `Error` 级别记录。默认配置下，发布到板子直接运行即可在控制台和日志文件中查看，不需要调试器。发送前不写成功日志；日志区分识别耗时、识别及发送总耗时，以及识别失败和发送失败。告警和识别结果入库尚未接入。

每台相机独立记录帧号起点，重复帧号忽略，帧号回退时重新设定起点，重新打开后状态重置。正常筛选以 SDK 帧号按顺序递增为前提；头文件未声明回调顺序、丢帧及重连后的帧号规则，需设备验证。跳过的帧号不补做，普通帧不会覆盖符合条件的通知。所有相机共享算力，识别慢时只保留最新的符合条件的通知，不保证每个选中帧都执行识别。回调中的帧号仅为触发信息：OrientationPosDetect 不接收帧号，实际识别哪一帧取决于 SDK。还需在 Linux ARM64 设备上确认 SDK 支持从回调以外的后台线程执行识别。

关闭单个相机先注销 ID、丢弃通知并等待正在执行的识别，然后停止录像和关闭相机。服务停止先取消并等待消费者，再关闭相机。取消令牌无法中断已进入的原生调用，SDK 不返回时关闭也会等待。关闭失败后该相机保持注销状态，需关闭成功并重新打开才恢复识别。

没有额外调用 ClearDetectResult：当前 SDK 未说明是否需要逐帧清理，避免擅自改变结果生命周期。其他业务如直接使用 IDetectManager，仍需自行协调相机生命周期，实时识别统一走调度器。

按相机 ID 管理依赖 SDK 在 CloseCam 成功返回后停止旧回调，再重新打开相机；不再维护额外的 Session。

## 当前 PLC 联调约定

接收固定 8 字节，按完整报文解析，模式和车速为大端整数；前两个字节 00 03 表示自动模式。首次模式 3 只启动一趟巡检，重复报文和重连不会重复创建记录。巡检结束暂未接入，停车、模式切换和断线不自动结束录像或识别；宿主退出时停止录像和关闭相机，暂不填写业务结束时间。录像目录按保存根目录/巡检ID/camera-转义后的业务Id 分开。

仅 192.168.8.16（002-车头）启用识别，FrameInterval 配置为 1；另一台保留录像。全局默认帧间隔仍为 5。启动校验最多允许一台启用识别，因为结果报文不带相机编号。每次 SDK 返回成功，立即发送两个大端中心点字节和状态字节 01（就绪=1，结束=0）；例如 centerX=300 发 01 2C 01。不按 1080 缩放或截断，只拒绝两字节无符号整数无法表示的值。TCP 禁用 Nagle，发送最多等待 1 秒，失败关闭连接并由通信循环重连，不补发旧结果。写入 TCP 成功不等于 PLC 已执行。
